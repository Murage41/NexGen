# Employee Compensation and Payroll

This guide defines the production workflow for employees, compensation,
earnings, deductions, and payments in NexGen.

## What Changed

The old employee record assumed one fixed daily wage. The new model separates:

- Employment details: name, phone, job title, employment type, dates, status.
- System access: admin or attendant role and a four-digit PIN.
- Compensation plan: effective-dated rules used to earn money.
- Earnings: immutable amounts generated from closed shifts or pay periods.
- Payroll: calculated, approved, paid, reversed, or voided records.

Existing data is preserved. Migration `032` converts every existing
`daily_wage` to a fixed-per-shift compensation plan. Migration `033` snapshots
legacy closed-shift wages without recalculating them. Migration `034` adds the
payroll ledger. The old columns remain for compatibility.

## Compensation Methods

A plan may contain up to eight components:

| Method | Meaning | Typical schedule |
|---|---|---|
| Fixed per shift | A fixed amount for each closed shift | Daily or weekly |
| Fixed salary | A fixed amount for a pay period | Weekly, biweekly, monthly |
| Percentage of sales | A percentage of shift sales | Daily or weekly |
| KES per litre | A fixed rate for litres sold in a shift | Daily or weekly |

Percentage and per-litre components may apply to all fuel, petrol only, or
diesel only. A component may also have a minimum or maximum amount. Multiple
components can be combined, for example:

```text
KES 750 per shift + 0.5% of sales
KES 8,400 per week + KES 0.75 per litre
KES 48,000 per month
```

Use a fixed salary for monthly, weekly, or biweekly wages. Use fixed per shift
only when the employee earns the amount by completing a shift.

## Effective Dates

Compensation plans are versioned rather than edited in place.

- A new employee receives a starting plan during creation.
- A later plan must start after the employee's latest plan.
- An employee with an open shift cannot receive a new plan.
- A new plan cannot be backdated across an already closed shift.
- The old plan ends on the calendar day before the new plan starts.
- Closed shifts retain the plan and earning values used when they closed.

This prevents a later salary change from rewriting historical payroll.

## Shift Earnings

When a shift closes, the backend calculates all shift-based components:

- Fixed-per-shift amount.
- Percentage of the applicable recorded sales.
- Per-litre rate against the applicable recorded litres.
- Any configured minimum or maximum.

The calculation uses decimal rounding to two currency places and is
idempotent. Retrying a shift close cannot create duplicate earnings.

Fixed periodic salary is not generated by shift close. It is generated when
the matching payroll period is calculated.

## Payroll Lifecycle

Payroll uses these states:

1. `calculated`: Draft totals and lines are available for review.
2. `approved`: Earnings and deductions are locked and posted.
3. `partially_paid`: At least one payment is posted and a balance remains.
4. `paid`: The full net amount has been paid.
5. `void`: The run was cancelled with a reason and its links were reversed.

A calculated fixed salary remains draft and is excluded from financial
reports. Approval promotes it to approved employee earnings. This is the
accounting posting boundary.

A payroll run only collects earnings whose compensation plan has the same pay
schedule. A monthly run cannot collect weekly or daily earnings.

Only one active payroll run can exist for the same schedule and date range.
Void the incorrect run before calculating a corrected replacement.

## Deductions and Staff Debt

Deductions are added while a run is calculated and still editable.

- Staff debt deductions require an authorization reference.
- A deduction cannot exceed gross earnings.
- A staff debt deduction cannot exceed the employee's outstanding staff debt.
- Staff debt is reduced only when payroll is approved.
- Voiding the run restores approved staff-debt allocations.
- Statutory, advance, and manually authorized deductions remain separate types.

Payroll deductions do not change how the original staff debt or shift deficit
was recorded. They create an auditable allocation against that existing debt.

## Payments and Shift Accountability

Payroll payments may use cash, M-Pesa, bank transfer, or cheque.

- A direct admin payment is recorded without a shift link.
- Cash or M-Pesa may optionally be paid from an open shift.
- A shift-linked payroll payment is an outflow from that shift's drawer.
- Direct bank, cheque, cash, or M-Pesa payments do not alter a shift unless an
  open shift is explicitly selected.
- A payment cannot exceed the payroll line balance.
- Posted payments can be reversed with a reason.
- A payroll run cannot be voided until all posted payments are reversed.

This is separate from customer debt collection. Customer debt receipts remain
part of the cash or M-Pesa actually received during the linked shift; they are
not added on top of received collections.

## Desktop Workflow

### Add or update an employee

1. Open **Employees**.
2. Select **Add Employee**.
3. Enter employment and access details.
4. Add one or more starting compensation components.
5. Save the employee.
6. Use the pencil action for later profile changes.
7. Use the compensation action to create a future plan version.

### Run payroll

1. Open **Payroll**.
2. Select **Calculate Payroll**.
3. Choose the schedule and exact period.
4. Review each employee's earnings.
5. Add authorized deductions while the run is calculated.
6. Approve the run.
7. Record one or more payments until the balance is zero.
8. Expand an employee line to review earnings, deductions, and payments.

Use reversal and void actions instead of deleting financial records.

## Mobile Workflow

Admin users can open **More**, then **Employees** or **Payroll**.

- Employees shows compensation, approved earnings, payroll due, and staff debt.
- Employee profiles and future compensation plans can be maintained on mobile.
- Payroll runs can be calculated, reviewed, and approved.
- Approved payroll can be paid directly or from an open shift when eligible.

Attendants do not receive admin employee or payroll routes.

minimum sequence is:

```powershell
cd E:\NexGen

# Back up E:\NexGen\backend\data and verify nexgen.db exists in the backup.

git pull --ff-only origin main
npm.cmd install

cd ..

npm.cmd run station:bg
```

The migration is additive, but the backup is still mandatory.
